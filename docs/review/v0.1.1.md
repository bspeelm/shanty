# Review packet — v0.1.1

A behaviour change on something already installable, and a test that was
proving less than it appeared to.

## What changed

**Text from the server has bidirectional formatting characters removed before
it is displayed.** v0.1.0 removed terminal control sequences but deliberately
left these in place. That decision was wrong, and ADR-015 records why.

An override or an isolate forces the display order of letters, so a server
could make a track title read in an order its characters do not have. The
screens join a title and a duration into one line, so an unterminated one also
changed the layout of the rest of that row.

Removed: `U+202A`–`U+202E` and `U+2066`–`U+2069`. Kept: `U+200E` and `U+200F`,
which order neutral characters only and cannot reverse letters.

Right-to-left scripts are unaffected. They render from the directional
properties of the letters themselves and need no control characters, which is
the fact the original decision got wrong.

**`TestChildProcessHygiene` can now see a credential in mpv's environment.** It
planted its canary as `SHANTY_TEST_CANARY=<token>`, so the token could not be
searched for in the place it would most matter. Adding the token alone to the
child's environment passed the test. The canary is now a value nothing uses.

## The five answers

Unchanged from v0.1.0 except where noted. `docs/review/v0.1.0.md` has them in
full.

**Paths written, and what permits each.** Unchanged.

**How bytes enter, and the gate on each.** Unchanged, with one gate
strengthened: text from the server now passes through a filter that removes
bidirectional formatting as well as terminal controls.

**External processes and their environment.** Unchanged: one program, mpv, run
with fixed flags and the inherited environment. What changed is the test. mpv
inherits the whole environment because PipeWire, PulseAudio and ALSA read from
it, and that is safe only because shanty adds nothing of its own. The test that
keeps that true could not previously detect the credential itself.

**Deletion paths.** Unchanged.

**Which check proves each claim.** Two additions:
`TestSanitiseRemovesBidirectionalFormatting` and `TestSanitiseRemovesTheReversal`
for the display order, `TestSanitiseKeepsTheDirectionalMarks` pinning the
narrower rule so widening it takes a decision.

## Where to look hardest

**`internal/tui/sanitise.go`.** Two predicates now, `control` and `bidi`. The
ranges are the whole decision: `U+202A`–`U+202E` is the embedding and override
block, `U+2066`–`U+2069` the isolates. Satisfy yourself that `U+200E` and
`U+200F` genuinely cannot reverse a run of letters, because keeping them is a
deliberate narrowing and the test pins it.

**`internal/mpv/mpv_test.go`.** The canary and the searched-for values must
stay distinct. If a later change makes the canary a credential again, the test
silently stops covering the credential.

## What was not verified

Everything in the v0.1.0 packet still applies. Nobody has heard a release
binary play, audio output is untested in CI, only Navidrome has been tried, and
only Linux has been run.

One item is closed since v0.1.0: the release machinery has now run. v0.1.0 was
built, signed, published, downloaded, checksum-verified, provenance-verified
and executed. This is its second run.

These notes were written by the author of the code. The bidirectional finding
came from a reviewer, not from the author, which is the first time a finding in
this project has.
