# Review packet — v0.3.0

The comforts, cut down to one. Cover art, loudness levelling, and a bug in
playlist editing that made the feature reach one album.

## What shipped

**Album art.** An album shows its cover, drawn with the kitty graphics protocol
or the iTerm2 one. `:art` shows it filling the screen. A terminal that draws no
pictures is asked for none and sent none, and `shanty doctor` says which of
those it found.

**`:auto-vol`.** Loudness levelling from the gain a tagger measured, applied by
mpv as a volume change and remembered in `config.toml`.

**`e` leaves playlist edit mode**, where `esc` used to. Edit mode shows the
library so that tracks can be found anywhere in it, and `esc` leaving the
playlist meant it could reach exactly one album.

Two of the four milestone issues were decisions rather than features: the
§0 budget (#35) and, inside it, what an estimate is worth.

## What a reviewer should weigh first

### The interface now emits bytes it does not understand

Every screen before this was text that `fit` and `lipgloss.Width` could
measure. A graphics escape is not that, and the difference produced five bugs
of one kind:

- It does not take the space it appears to. The terminal moves the cursor past
  a picture, so rows reserved for one were added to rows it had already taken.
  `C=1` is the placement saying not to.
- It does not go away when text is drawn over it. It is an overlay the terminal
  holds until told otherwise.
- It does not keep its shape. Given a width and a height it fills both, so a
  square cover stretched across a screen five times as wide as it is tall.
- It is not sent unless the row it sits on changed. Leaving `:art` is the same
  album, so the title row was identical and the row carrying the delete was
  never written.

The first three are visible in a rendered frame and a frame test finds them.
The fourth exists only in what the renderer chose to send, and needed a test
comparing commands rather than frames. **`internal/tui` still does no I/O**:
it is handed rendered lines and never learns what a protocol is.

### Two guards on bytes a server chose

**A byte cap does not bound an image.** A few hundred kilobytes of PNG can
declare itself 30000×30000, which decodes to 3.6 GB. The header is read and
the dimensions checked before anything is decoded.

**The cover art identifier is opaque.** It may hold path separators, may be
`..`, may be longer than a filesystem will take. It is hashed rather than
escaped, so no value a server returns names a file outside the cache.

### Loudness levelling is somebody else's measurement

shanty applies a number it did not compute and cannot. The Subsonic API has no
endpoint for writing tags, and reaching the library's files means filesystem
access to the server, which §3 defers. So the correction is a constant gain
rather than a filter, dynamics are untouched, and an untagged track plays as it
is.

The cost is that **it is invisible when it does nothing**. Turning it on over
an untagged library sounds exactly like turning it on over a library that
needed no correction. Both wiki pages say so and say where the answer is; the
interface cannot say, because it is handed audio rather than files.

## The five answers

Unchanged from v0.2.1 except as follows.

**Paths written.** Two new, both inside the four directories:
`$XDG_CACHE_HOME/shanty/covers/` at 0700 with images at 0600, and
`auto_volume` in the existing `config.toml`.
`TestCoversAreInsideTheCacheDirectory` holds the first against §8.

**How bytes enter.** One new source: **cover art from the server**, capped at
8 MiB on the wire, checked to be an image before it is believed to be one, and
checked by header for size before it is decoded. A server that answers with an
error envelope, an HTML page or a decompression bomb is refused, and the
refusal names which.

**External processes.** Unchanged. Two, mpv and shanty itself.

**Deletion paths.** Unchanged. The cache holds derived data and `uninstall`
removes it with the other three.

**Which check proves each claim.** New:

| claim | proof |
|---|---|
| a huge header is never decoded | `TestAnImageWhoseHeaderIsHugeIsNeverDecoded` |
| a hostile identifier stays in the cache directory | `TestAnIdentifierThatIsAPathStaysInTheDirectory` |
| a terminal without graphics is asked for nothing | `TestATerminalThatDrawsNoPicturesAsksForNoneAndIsSentNone` |
| a cover gives way to the tracks | `TestACoverGivesWayOnlyToTracksThatExist` |
| the picture is taken away when it is put away | `TestTheBigCoverComingAndGoingRepaints` |
| levelling reaches the player and is remembered | `TestAutoVolumeReachesThePlayerAndIsRemembered` |
| a remembered setting is applied at startup | `TestAutoVolumeIsAppliedAtStartup` |
| the wiki's command table is the command set | `TestTheWikiTableIsWrittenFromTheCommands` |

## Where to look hardest

**`cover.Fit` and `cover.Block`.** The arithmetic that keeps a picture the
right shape assumes a cell is twice as tall as it is wide, which is a constant
rather than a question asked of the terminal. It is right enough at the size a
cover is drawn and wrong for anybody whose font says otherwise.

**`checkCoverArt` in `cmd/shanty/doctor.go`.** It reports what shanty decided
from `TERM`. That check exists because the answer is otherwise invisible, and
the same argument applies to levelling, which has no such check.

**ADR-022.** It raises §0 to 6,700 against a measured number and records what
ADR-021's estimate missed. The conclusion worth arguing with is the last
paragraph: that the next estimate will also be short, and the answer is a
smaller claim about what an estimate is worth rather than a bigger cap.

## What was not verified

**iTerm2 has never drawn a cover.** Detection, the escape sequence and its byte
length are covered by tests. No iTerm2 has run one. It is also the protocol
whose picture is drawn into cells rather than over them, so the padding rows
this sends may overwrite it, and `cover.Clear` returning nothing for it is
reasoning rather than observation.

**Non-square covers inline.** `Fit` is held against square, wide and tall
images, but the fake serves a 1×1 square PNG, so the one wiring that shapes the
inline cover is an equivalent mutant.

**Sixel is not built** and is #50. The terminals that speak it rather than the
kitty protocol are the ones people already have — xterm, foot, Konsole, and
VTE-based terminals — so this is a gap rather than a rounding error.

**Whether `:auto-vol` takes effect mid-track.** mpv builds its audio filter
chain at file load, so the toggle may not apply until the next track. It was
tried and worked; which of the two happened was not established.

**Everything v0.2 left unverified is still unverified.** The endpoints added
then have run only against the fake in this repository.
