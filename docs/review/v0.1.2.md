# Review packet — v0.1.2

One bug, in code that was released twice without it being noticed.

## What changed

**Error messages are now shown on every screen.** They were rendered in one
place — the body of an empty list — so a failure on a screen with artists,
albums or tracks loaded produced no visible change at all.

The case that matters is mpv stopping while an album plays. shanty set the
message "mpv stopped, restart shanty to play again" and, with a track list on
screen, the music stopped and nothing was displayed.

The last row of the frame now carries the message when there is one and the key
help when there is not.

**A second problem, found while fixing the first.** Messages contain line
breaks, because the errors producing them put the cause on one line and the
remedy on the next, and the filter that removes terminal control characters
removes the break with them. The first version of the fix rendered
`exit status 1restart shanty to play again`. Breaks are turned into separators
before the message is filtered.

## Why it was not caught

Both reasons are about tests looking in the wrong place, and both are worth
knowing because neither is specific to this bug.

`TestADeadPlayerBecomesAMessageAndNotARestart` asserted on the model's status
field rather than on the rendered frame. It passed whether or not the message
ever reached the screen.

Every golden file covering an error was generated from a model with nothing
loaded. The only error path they pinned was the one that happened to work.

Both now do the opposite: the test reads the rendered frame with a list loaded,
and there is a golden file for a failure on a populated screen.

## The five answers

Unchanged from v0.1.1. `docs/review/v0.1.0.md` has them in full. Nothing about
paths written, bytes entering, processes executed or deletion paths is affected
by this change.

One addition to the last: `TestAMultiLineMessageIsJoinedRatherThanConcatenated`
proves a message with a line break renders as one row rather than two halves
run together.

## Where to look hardest

**`internal/tui/view.go`, `footer`.** One row serves two purposes. Satisfy
yourself that a message can never be lost because something else claimed the
row, and that the ordering is right: the line break becomes a separator before
the filter runs, because the filter would otherwise remove it.

**`internal/tui/golden_test.go`.** The golden files are only as good as the
models they are generated from. This bug existed because every error case was
generated from an empty one. When a screen gains a state, ask whether the
golden covering it exercises the state or only the shape.

## What was not verified

Everything in the v0.1.0 packet still applies: nobody has heard a release
binary play, audio output is untested in CI, only Navidrome has been tried, and
only Linux has been run.
