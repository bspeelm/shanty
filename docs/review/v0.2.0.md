# Review packet — v0.2.0

A daily driver. Sixteen issues, and the four that matter to a reviewer are the
ones that changed what shanty is rather than what it can do.

## What shipped

**A session that outlives its terminal.** `:headless` closes the interface and
leaves the music playing, with the server still told what was listened to.
Seven commands drive it from any shell, and running `shanty` again takes it
back. ADR-018 records why this is not the daemon `PLAN.md` §3 refuses.

**Search, starring, playlists and a queue you can see.** `:search` reaches the
whole server where `/` only narrows what is loaded. `*` stars, `gs` lists what
is starred. `gp` lists playlists, `:playlist edit` fills one against the
library. `gq` shows the queue, `a` and `A` add to it.

**Plays that could not be reported are kept** in the state directory and sent
when the server takes them again, with the time they happened.

**The keys are a table of named actions**, bindable from `config.toml`, and
held against `wiki/Keys.md` in both directions. `:wiki` explains the commands
without leaving shanty.

## What a reviewer should weigh first

Three things in this release are new in kind, not degree.

**shanty now starts a copy of itself.** `:headless` re-execs the binary with
`SysProcAttr{Setsid: true}` and hands it the queue. It is the first process
shanty runs that is not mpv, and §7's rule applies to it: no credential in a
child's arguments or environment. The handoff carries track identifiers and the
child reads the credential itself.

**There is a second socket, and it accepts commands from another process.**
ADR-001 modelled the mpv socket as an output — the credential leaves through
it. The control socket is an input. It takes a closed set of eight verbs, none
of which names a file or a program, which is the reason shanty answers on its
own socket rather than letting `shanty pause` drive mpv's. mpv's IPC accepts
`run`, `subprocess` and `load-script`.

**One file is written outside the four directories.** The shell completion,
installed by whatever installs the binary, beside `~/.local/bin/shanty` which
was already outside them. §8 names it and `shanty uninstall` removes it.

## The five answers

### 1. Every path it writes to, and what permits each

| path | mode | written by |
|---|---|---|
| `$XDG_CONFIG_HOME/shanty/config.toml` | 0644 | `setup`, atomically |
| `$XDG_CONFIG_HOME/shanty/credentials.toml` | 0600 | `setup`, atomically |
| `$XDG_STATE_HOME/shanty/plays.jsonl` | 0600 | a play the server refused |
| `$XDG_RUNTIME_DIR/shanty/` | 0700 | before either socket is opened |
| `$XDG_RUNTIME_DIR/shanty/mpv.sock` | mpv's own | mpv |
| `$XDG_RUNTIME_DIR/shanty/control.sock` | 0600, set explicitly | a detached session |
| `$XDG_DATA_HOME/bash-completion/completions/shanty` | 0644 | `completions install` |
| `$XDG_CONFIG_HOME/fish/completions/shanty.fish` | 0644 | `completions install` |

New since v0.1: the backlog, the control socket, and the two completion files.
The completions are the only things outside §8's four directories, and the only
ones written by the installer rather than by shanty running.

`TestIsolationTheBacklogIsTheOnlyThingInTheStateDirectory` and
`TestIsolationOnlyTheInstallerWritesOutsideTheFourDirectories` hold the write
set exactly, and the second asserts that ordinary commands write no completion.

### 2. Every way bytes enter the process, and the gate on each

| source | gate |
|---|---|
| the server's JSON | capped reader, fuzzed decoder, one sanitising function before display |
| mpv's IPC replies | bounded scanner, replies routed by request id |
| the control socket | 0600 in a 0700 directory; a closed verb set; a protocol version; a 3s deadline |
| the handoff on stdin | 1 MiB limit, a protocol version, refused if it names no tracks |
| `config.toml` | TOML only; an unknown key binding is reported, not obeyed |
| the backlog file | a line that will not parse is skipped, not fatal |

The control socket and the handoff are new. Both are reachable only by the
account that owns the runtime directory.

### 3. Every external process it executes, and with what environment

Two programs now, where v0.1 had one.

**mpv**, with fixed flags, an inherited environment and no credential in argv.
Unchanged except that it is now started in its own session, so the terminal
cannot signal it and `Close` is its only owner.

**shanty itself**, as `shanty _session`. Argv is exactly two words. The
environment is inherited for the same reason mpv's is — the sound server is
found through it — and nothing of shanty's is added. The queue arrives on a
pipe rather than on the command line.

`TestChildProcessHygiene` covers mpv. The session child's argv is asserted, and
`TestTheHandoffCarriesTheQueueAndNoCredential` reads the bytes rather than the
code.

### 4. Every deletion path, and what happens when one is pointed wrong

| what | where | guard |
|---|---|---|
| the four directories | `uninstall` | refuses through a symlink; refuses while a session is playing |
| the completion files | `uninstall` | exact paths, named in §8 |
| a stale socket | `mpv.Start`, `control.Listen` | dialled first; a live one is never removed |
| the backlog | `backlog.Replace` | written to a temporary file and moved over |
| a playlist | `:playlist delete` | asks, naming it and its size; anything but `y` is no |

The socket guard is new and fixes a bug that shipped in v0.1: `Start` removed
whatever was at the path, so a second shanty orphaned the first mpv for the
rest of its life, holding a credentialed stream URL.

### 5. Which check proves each claim

| claim | proof |
|---|---|
| a detached session still reports plays | `TestASessionStillReportsPlays` |
| exactly one process drives mpv | `TestHandingOverReleasesThePlayerAndTheQueue` |
| a track ending mid-handover is reported once | `TestATrackEndingDuringTheHandoverIsReportedOnce` |
| the control socket refuses what is not a verb | `TestAVerbTheSessionDoesNotKnowIsRefusedBeforeItArrives` |
| a stopping session answers before it goes | `TestAStoppingSessionAnswersFirst` |
| a refused play is kept and sent later | `TestAPlayTheServerWouldNotTakeIsKept` |
| an accepted play is not sent twice | `TestPlaysTheServerTookAreNotSentAgain` |
| every bound key is documented, and the reverse | `TestEveryKeyIsDocumentedAndEveryDocumentedKeyIsBound` |
| every command is explained, and the reverse | `TestEveryCommandIsExplainedAndEveryExplanationIsACommand` |
| deleting a playlist asks first | `TestDeletingAPlaylistAsksFirstAndNamesIt` |

## Where to look hardest

**The handover window.** For a few hundred milliseconds two processes hold one
mpv. The interface stops advancing the queue the moment it starts a session
rather than when the session reports success, so a track ending in that window
is reported once rather than twice. If the session never starts, one play
report is lost — chosen over double-counting on the path that works.

**`byName` in `cmd/shanty/app.go`.** Playlist names are not unique on a server;
only identifiers are. Two matches is refused rather than resolved. This is the
one place a wrong guess would delete something.

**`OlderThan` in `internal/mpv`.** The minimum is 0.24.0 because
`--prefetch-playlist` arrived there. A version shanty cannot read is treated as
new enough, on the grounds that refusing to run against something unrecognised
is worse than trying.

## What was not verified

**The new endpoints have never run against a real server.** The integration job
covers `Ping`, `Artists`, `Artist`, `Album`, `StreamURL` and `Scrobble`.
Everything v0.2 added to `internal/subsonic` — `search3`, `star`, `unstar`,
`getStarred2`, the five playlist calls, `savePlayQueue`, `getPlayQueue`,
`startScan`, `getScanStatus` — has only run against the fake in this
repository, which was written alongside the client and agrees with it by
construction.

The parameters most likely to be wrong are the ones a fake cannot disagree
about: `songIndexToRemove` counting positions rather than identifiers,
`position` in milliseconds, and each starrable kind under its own parameter
name.

**macOS is unbuilt and untested.** The cross-build compiles it; nothing runs
it. ADR-012 is still open.

**A session has not been left running for a long time.** Its exposure is
bounded by its queue, which is the argument ADR-018 rests on, but nothing has
tested a session outliving a credential rotation.
