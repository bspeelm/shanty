# Review packet — v0.1.0

The first release.

## What shipped

A terminal client for a Subsonic server. It reads two configuration files —
writing them itself on a first run — asks the server what music it has, shows
three lists to walk down, and plays a chosen track by handing a URL to **mpv**,
a separate media player it starts and talks to over a unix socket. When a track
finishes it tells the server the track was played. It can check its own setup
and say what is wrong, and remove everything it ever wrote.

It decodes no audio itself. mpv does that, in its own process, and ADR-011 says
why: the alternative puts the parsing of untrusted audio inside the program
holding the credential.

## The five answers

The §7.2 exit exam, answered here rather than asked. These are the facts a
reviewer would otherwise have to reconstruct, and they are what the rest of
this document is evidence for.

### 1. Every path it writes to, and what permits each

| path | mode | written by |
|---|---|---|
| `~/.config/shanty/` | 0700 | `writeAtomic`, on the way to the two files |
| `~/.config/shanty/config.toml` | 0644 | `Config.Save` — nothing secret in it |
| `~/.config/shanty/credentials.toml` | 0600 | `Credentials.Save` — refuses to hold a plaintext password |
| `$XDG_RUNTIME_DIR/shanty/` | 0700 | `Paths.EnsureRuntime`, at first play |
| `$XDG_RUNTIME_DIR/shanty/mpv.sock` | mpv's | mpv, not shanty |

`~/.local/state/shanty` and `~/.cache/shanty` are declared in §8 and **nothing
writes them in v0.1** — the backlog is v0.2 and cover art is v0.3.

Every write goes through `internal/config`, and the mode is set before the
rename, so nothing is ever observed at the wrong permissions. Nothing else on
the machine is touched: `TestIsolationTouchesNothingOfAnybodyElses` plants a
`.bashrc` and a `~/.config/mpv/mpv.conf` and reads them back byte for byte.

### 2. Every way bytes enter the process, and the gate on each

| source | gate |
|---|---|
| HTTP responses from the one configured server | `io.LimitReader` at 16 MiB, then `decode`, which `FuzzDecode` targets |
| mpv's replies and events over the socket | `bufio.Scanner` capped at 1 MiB per line; an unparseable line is skipped, not fatal |
| `config.toml` and `credentials.toml` | `go-toml`; the credentials file is refused outright unless 0600 |
| what you type during `setup` | one `bufio.Reader`; the credential through `term.ReadPassword`, never echoed, terminal required |
| mpv's stderr | an `io.Writer` the caller supplies; nil in production |

**Audio never enters this process.** mpv fetches the stream itself over the URL
it was handed. That is the point of ADR-011.

### 3. Every external process it executes, and with what environment

Two call sites, one program:

- `internal/mpv.Start` runs `mpv --no-config --no-video --idle=yes
  --prefetch-playlist=yes --input-ipc-server=<socket>`. There is no flag
  passthrough; §3 keeps shanty out of the business of managing anyone's mpv.
- `doctor` runs `mpv --version` and prints the first line.

Both inherit the environment whole, because PipeWire, PulseAudio and ALSA read
from it. **Nothing of shanty's is added to it** — the credential travels over
the socket, which is why there is a socket. `TestChildProcessHygiene` plants a
credential in the parent's environment, confirms it reaches the child, and then
asserts shanty's own never appears in argv or environ; on Linux it reads
`/proc/<pid>/` as well.

### 4. Every deletion path, and what happens when one is pointed wrong

| what | where | guard |
|---|---|---|
| its own temp file | `writeAtomic` | named uniquely by `os.CreateTemp`, removed unconditionally |
| a stale mpv socket | `mpv.Start` | unconditional `os.Remove` of `Options.Socket` — **the least guarded deletion in the program** |
| the four directories | `uninstall` | reads `Paths.All()`, refuses to delete a root that is a symlink |

`os.RemoveAll` unlinks a symlink it meets inside rather than following it —
verified, not assumed. The remaining exposure is that `mpv.Options.Socket` is a
settable field with no validation; in every current caller it comes from
`Paths.Socket()`.

### 5. Which check proves each claim

| claim | proof |
|---|---|
| credentials file is 0600 or it refuses | `TestCredentialsPermissions` |
| shanty never writes a plaintext password | `TestNoPlaintextPasswordPersisted`, and the type `Save` marshals has no such field |
| no credential in any child's argv or env | `TestChildProcessHygiene` |
| writes confined to four directories | the four `TestIsolation*` tests, with a ran-count assertion in CI |
| every HTTP client has a timeout | `TestClientTimeouts`, by reflection |
| no `panic(`, no TLS bypass, no I/O in the TUI | `make budgets` |
| no frame carries a terminal escape | `TestNoFrameEverCarriesAnEscape` |
| every doctor failure names its fix | `TestEveryFailureAndWarningCarriesItsFix` |
| the installer asks for what the release publishes | `TestTheInstallerAsksForWhatTheReleaseProduces` |
| it works against a real server and real mpv | the `integration` job — Navidrome in a container, mpv 0.37 |
| the README's commands exist | `cmd/shanty/docs_test.go` |

## Where to look hardest

Not a questionnaire. These are the places where reading beats testing, in the
order I would read them.

**`internal/config/credentials.go`.** The permission check is one bitmask
expression. Get it wrong and a world-readable credential is accepted in
silence. `Save` marshals a type with no password field, so the promise is
structural rather than checked — confirm that is still true.

**`internal/mpv/mpv.go:83`.** `os.Remove(opt.Socket)`, unconditional, before
spawning. Every caller passes `Paths.Socket()`; nothing enforces that.

**`internal/subsonic/auth.go`.** `Redact` works from a list of parameter names.
A fourth authentication mode with a new parameter is logged in clear until
someone remembers this list. Its test covers what today's three constructors
emit, which is the most a test can know.

**`cmd/shanty/uninstall.go`.** The only `RemoveAll` in the program. Its path
comes from `Paths.All()` and nothing else — satisfy yourself there is no route
by which that returns something not shanty's.

**`scripts/budgets.sh`.** Weakening it is invisible: a loosened grep still
prints a number and still says the budget passed. `set -eu` bit once already —
a `find` over a directory that did not exist killed the script silently and
every check after it simply did not run.

**`.github/workflows/release.yml`.** The signing step's subject list is the
trust boundary; an artifact not listed there ships unattested beside ones that
are.

## What was not verified

- **Nobody has heard a release binary play.** A development build has been
  played by hand on the maintainer's machine against a real Navidrome. The
  artifact this tag produces has not.
- **`release.yml`, goreleaser, the signing step and `install.sh` have never
  run.** This tag is the first execution of all four.
- **Audio output is untested in CI.** A runner has no sound card, so the
  integration job gives mpv a null ALSA device. Everything up to the speaker is
  verified; the speaker is not.
- **Only Navidrome has been tested.** ADR-007 makes every other Subsonic server
  best-effort and none has been tried.
- **Only Linux has been run.** darwin is cross-compiled in CI and never
  executed, and ADR-012 records that §8's filesystem contract does not describe
  macOS correctly yet.
- **These notes were written by the author of the code.** §7.5 asks for the
  risk list to be drafted by a model other than the one that wrote it. It was
  not, so this is a floor: what it points at is where the author already
  looked.
