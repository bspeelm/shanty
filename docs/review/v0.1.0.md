# Review packet — v0.1.0

The first release. Answer the questions marked **ANSWER HERE**; the release
workflow refuses to build a tag while any remain, and refuses again while
`docs/reviewed.md` has an unread surface.

## 1. What shipped

A terminal client for a Subsonic server. It reads two configuration files,
asks the server what music it has, shows three lists to walk down — artists,
then that artist's albums, then that album's tracks — and plays a chosen track
by handing a URL to **mpv**, a separate media player it starts and talks to
over a unix socket. When a track finishes it tells the server the track was
played. It can also check its own setup and report what is wrong, and remove
everything it ever wrote.

It decodes no audio itself. mpv does that, in its own process, and the reason
is in ADR-011: the alternative puts the parsing of untrusted audio inside the
program that holds the password.

## 3. Review cards

One per load-bearing surface. **These were written by the author of the code,
not adversarially, which §7.5 asks for and this release did not get.** Treat
them as a floor: a guided tour shows the good rooms. At least one finding
should come from outside these cards, and a read that turns up nothing outside
them is a finding about the tour rather than evidence about the code.

The reading guide in `load-bearing-2026-09.md` covers the first three in more
detail, including mutations to plant. It predates four of these seven.

---

### `internal/config` — reads and writes both files

*What it does now.* Resolves four directories from the environment without
creating any. Reads and writes `config.toml` at 0644 and `credentials.toml` at
0600. Refuses to start if the credentials file is readable by anyone else.
Never writes a plaintext password.

*What could go wrong.* The permission check is one bitmask expression
(`perm &^ CredentialsMode != 0`); get it wrong and a world-readable credential
is silently accepted. `writeAtomic` sets the mode before the rename — reversed,
there is a window at 0644 and nothing fails. `Paths.All()` is the write set
both `uninstall` and the isolation suite read; a fifth directory resolved
anywhere and left out of it is one neither ever looks at.

*How to check it.* `go test ./internal/config/ -v` — 53 PASS lines. Then plant
the mutation in the reading guide and watch `TestCredentialsPermissions` fail
on 0640.

---

### `internal/subsonic` — the only package that touches the network

*What it does now.* Builds authenticated URLs, decodes responses, caps how much
it reads, and redacts credentials before anything is logged. `make budgets`
asserts that this package and its fake are the only two importing `net/http`.

*What could go wrong.* `Redact` works from a list of parameter names, so a
fourth authentication mode with a new parameter is logged in clear until
someone updates the list. The oversize check rejects a body of exactly 16 MiB
as oversized, which is a false positive judged acceptable. `decode` trusts
`status == "ok"`, so every caller nil-checks its own payload — satisfy yourself
they all do.

*How to check it.* `go test ./internal/subsonic/... -v` — 46 PASS lines.
`go test ./internal/subsonic/ -fuzz=FuzzDecode -fuzztime=60s`. Then
`grep -rn StreamURL --include='*.go' .` and satisfy yourself no caller logs it.

---

### `internal/mpv` — spawns a child process and owns its socket

*What it does now.* Starts one mpv with fixed flags, waits for its socket, and
sends every command over it, including the track load that carries the
credential.

*What could go wrong.* `Start` does an unconditional `os.Remove` on
`Options.Socket` before spawning; the path comes from `Paths.Socket()` in
normal use but the field is settable. Events are dropped when the channel
fills — a dropped `end-file` is an album that stops between tracks and says
nothing. The environment is inherited whole, on the reasoning that shanty adds
nothing of its own to it; check that reasoning by reading `Start`.

*How to check it.* `go test ./internal/mpv/ -race -v` — 10 PASS. Then plant a
stream URL in argv per the reading guide and watch `TestChildProcessHygiene`
fail.

---

### `cmd/shanty/uninstall.go` — deletes directories

*What it does now.* Removes the four directories in `Paths.All()`, prints which
it removed and which were already absent, and refuses to delete through a
symlink.

*What could go wrong.* It deletes with `os.RemoveAll`, so a wrong path is a
wrong tree, and the only thing keeping the path right is `Paths.All()`. The
`Lstat` check covers the four directories themselves and does not walk inside;
a symlink *within* one is unlinked rather than followed, which was verified
rather than assumed — `os.RemoveAll` over a directory containing a symlink to a
file outside removes the link and leaves the file. So the remaining question is
narrower than it looks: is `Lstat` on the four roots the right place, and is
there a path by which `Paths.All()` could ever return something that is not
shanty's?

*How to check it.* `go test ./cmd/shanty/ -run 'Uninstall|Isolation' -v`.
Then, on a scratch `$HOME` you do not mind losing, run the real binary's
`uninstall` and diff the tree.

---

### `bootstrap/install.sh` — runs unsigned, before anything exists to verify it

*What it does now.* Downloads an archive for this platform, verifies it against
`checksums.txt`, optionally verifies provenance with `gh`, and installs to
`~/.local/bin`.

*What could go wrong.* It is piped into `sh` from the internet, so every line
runs as you. It reports "checksum verified" only when it verified one and says
so plainly when it did not — read those branches and confirm neither can print
the reassuring line without having checked. **It has never been executed**: its
tests read the script's text and hold its filenames against goreleaser's, but
nothing runs it end to end.

*How to check it.* `go test ./bootstrap/ -v`. Read the script top to bottom;
it is 139 lines and that is the point.

---

### `scripts/budgets.sh` — enforces this project's restraint

*What it does now.* Counts dependencies, modules, code, comments, prose,
panics, `net/http` importers, TLS bypasses, and the binary; fails on any
breach.

*What could go wrong.* Weakening it is invisible: a loosened grep still prints
a number and still says the budget passed. The `set -eu` interaction bit once
already — a `find` over a directory that did not exist killed the script
silently, and every check after it simply did not run.

*How to check it.* Plant a violation of each budget and watch it refuse:
a `panic(` in non-test code, an `InsecureSkipVerify`, an `os` import in
`internal/tui`, 6,001 lines of code, a comment ratio over 25%.

---

### `.github/workflows/` — the release's provenance and its token scopes

*What it does now.* `ci.yml` runs seven jobs at `contents: read`. `release.yml`
is read-only at the top and grants `contents: write`, `id-token: write` and
`attestations: write` to one job. `outdated.yml` opens one issue a week.

*What could go wrong.* The release job signs whatever is in `dist/`, so the
subject list is the trust boundary — an artifact not listed there ships
unattested beside ones that are. The two gates that block a release are shell
`grep`s; one of them was wrong until an hour before this packet, matching six
of seven ledger rows because the seventh had a space in its name.
**`release.yml` has never run.**

*How to check it.* Read all three. `grep -n permissions .github/workflows/*.yml`
and satisfy yourself no job has more than it needs.

## 6. What the author did not verify

- **Nobody has heard a release binary play.** A developer build has been played
  by hand on the maintainer's machine; the artifact this tag produces has not.
- **`release.yml`, goreleaser, the signing step and `install.sh` have never
  run.** This tag is the first execution of all four.
- **Audio output is untested in CI.** A runner has no sound card, so the
  integration job gives mpv a null ALSA device. Everything up to the speaker is
  verified; the speaker is not.
- **Only Navidrome has been tested.** ADR-007 makes every other Subsonic server
  best-effort, and no other has been tried.
- **Only Linux has been run.** darwin is cross-compiled in CI and never
  executed, and ADR-012 records that §8's filesystem contract does not even
  describe macOS correctly yet.
- **The cards above are not adversarial.** §7.5 asks for them to be drafted by
  a model other than the one that wrote the code. They were not.
